# CUS-AUTH-004 · Account Link

## Objective
หน้าผูกบัญชี LINE เข้ากับบัญชีลูกค้าเดิม (เบอร์โทร/อีเมล) เพื่อรวมเป็นบัญชีเดียวและไม่ให้ข้อมูลซ้ำซ้อน

## User Story
> As a **ลูกค้าที่มีบัญชีอยู่แล้ว (Customer)**, I want **ผูกบัญชี LINE เข้ากับบัญชีเดิมด้วยการยืนยันเบอร์โทร**, so that **เข้าระบบด้วย LINE ได้โดยใช้ประวัติและสิทธิ์เดิมต่อ**.

## Entry Point
- ถูกส่งมาจาก LINE Login (CUS-AUTH-002) เมื่อตรวจพบบัญชีเดิมที่มีเบอร์/อีเมลตรงกัน
- ถูกส่งมาจาก Register (CUS-AUTH-003) เมื่อข้อมูลซ้ำกับบัญชีเดิม

## Exit Point
- ผูกสำเร็จ → Home (CUS-HOME-001)
- ข้ามการผูก/ยกเลิก → Login (CUS-AUTH-001)

## Components
- การ์ดแสดงบัญชีเดิมที่พบ (ชื่อ/เบอร์บางส่วนแบบปิดบัง)
- ฟิลด์กรอกรหัส OTP เพื่อยืนยันตัวตน + ปุ่มส่ง OTP ใหม่
- ปุ่มหลัก "ยืนยันการผูกบัญชี"
- ลิงก์ "ใช้บัญชีใหม่แทน"

## Validation Rules
- ต้องกรอก OTP ครบตามจำนวนหลักและยังไม่หมดอายุ
- OTP ต้องตรงกับเบอร์ของบัญชีเดิมที่พบ
- ปุ่มยืนยัน disabled จนกว่าจะกรอก OTP ครบ

## API Dependencies
- `GET /auth/me` — ตรวจสถานะบัญชี/ความเชื่อมโยงปัจจุบัน
- `PUT /customers/{id}` — ผูก LINE identity เข้ากับบัญชีลูกค้าเดิม
- _หมายเหตุ: endpoint ส่ง/ยืนยัน OTP ยังไม่ระบุใน API_Specification_v1_

## Edge Cases
- OTP ผิด/หมดอายุ → error ใต้ฟิลด์ + ขอ OTP ใหม่ (มี cooldown)
- เลือก "ใช้บัญชีใหม่แทน" → ไปสมัครใหม่ (CUS-AUTH-003)
- เครือข่ายล่มระหว่างผูก → error + ลองใหม่โดยไม่สร้างบัญชีซ้ำ
- บัญชี LINE นี้ถูกผูกกับบัญชีอื่นแล้ว → แจ้งเตือนและบล็อกการผูกซ้ำ

## Success Criteria
- บัญชี LINE ถูกผูกกับบัญชีลูกค้าเดิมเป็น identity เดียว
- ประวัติการจอง/สิทธิ์สมาชิกเดิมยังคงอยู่หลังผูก
- ป้องกันบัญชีซ้ำซ้อนและการผูกซ้อนทับได้
