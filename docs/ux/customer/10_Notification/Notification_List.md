# CUS-NOTI-001 · Notification List

## Objective
- แสดงรายการการแจ้งเตือนของลูกค้า: เตือนการจอง (Booking Reminder), โปรโมชัน, สมาชิก
- แยกสถานะอ่าน/ยังไม่อ่าน และนำทางไปจอที่เกี่ยวข้องเมื่อกด

## User Story
> As a **Customer**, I want **ดูการแจ้งเตือนทั้งหมดของฉัน**, so that **ไม่พลาดการเตือนนัดจอง โปรโมชัน และข่าวสารสมาชิก**.

## Entry Point
- จาก Home (CUS-HOME-001) ไอคอนกระดิ่ง
- จาก Profile (CUS-PROFILE-001) เมนู "การแจ้งเตือน"

## Exit Point
- กดการแจ้งเตือนประเภทจอง → CUS-BOOK / Booking Detail
- กดการแจ้งเตือนโปรโมชัน → จอโปรโมชัน/คูปอง
- กดการแจ้งเตือนสมาชิก → CUS-MEMBER-001
- กดไอคอนตั้งค่า → CUS-NOTI-002 (Notification Settings)
- ย้อนกลับ → จอต้นทาง

## Components
- ตัวกรอง/แท็บ: ทั้งหมด / การจอง / โปรโมชัน / สมาชิก
- รายการแจ้งเตือน: ไอคอนประเภท, หัวข้อ, ข้อความย่อ, เวลา, จุดสีบอก "ยังไม่อ่าน"
- ปุ่ม "ทำเครื่องหมายอ่านทั้งหมด"
- ไอคอนเข้าหน้า "ตั้งค่าการแจ้งเตือน"
- Pull-to-refresh + pagination ; empty state เมื่อไม่มี

## Validation Rules
- รายการเรียงจากใหม่ไปเก่า
- กดรายการ → เปลี่ยนสถานะเป็นอ่านแล้ว และนำทางตาม deep link ของรายการ
- แสดงเฉพาะการแจ้งเตือนของลูกค้าที่ล็อกอิน (ตาม tenant)
- ตัวกรองสะท้อนผลจาก API

## API Dependencies
- `GET /api/v1/notifications` — รายการแจ้งเตือนของลูกค้า (รองรับ filter/pagination)

## Edge Cases
- ไม่มีการแจ้งเตือน → empty state "ยังไม่มีการแจ้งเตือน"
- โหลดล้มเหลว → error + ปุ่ม "ลองใหม่"
- deep link ของรายการเสีย/ทรัพยากรถูกลบ → toast "เนื้อหานี้ไม่พร้อมใช้งาน"
- ทำเครื่องหมายอ่านทั้งหมดล้มเหลว → คงสถานะเดิม + retry
- ออฟไลน์ → แสดงรายการ cache พร้อมป้าย "ออฟไลน์"

## Success Criteria
- แสดงการแจ้งเตือนครบ เรียงจากใหม่ไปเก่า แยกอ่าน/ยังไม่อ่านชัดเจน
- กดรายการเปลี่ยนเป็นอ่านแล้วและนำทางถูกต้อง
- ตัวกรองและ "อ่านทั้งหมด" ทำงานได้
- เข้าหน้า CUS-NOTI-002 ได้จากหน้านี้
