# CUS-NOTI-002 · Notification Settings

## Objective
- ให้ลูกค้าเปิด/ปิดการแจ้งเตือนแยกตามประเภท: การจอง, โปรโมชัน, สมาชิก
- ตั้งค่าช่องทางรับ (Push / LINE / Email) ตามที่สนามรองรับ และบันทึกค่ากำหนด

## User Story
> As a **Customer**, I want **เลือกได้ว่าจะรับการแจ้งเตือนประเภทใดและทางช่องทางไหน**, so that **ได้รับเฉพาะข่าวสารที่ต้องการและไม่ถูกรบกวนเกินจำเป็น**.

## Entry Point
- จาก CUS-NOTI-001 (Notification List) ไอคอนตั้งค่า
- จาก CUS-SET-001 (Settings) เมนู "การแจ้งเตือน"

## Exit Point
- บันทึก/สลับสวิตช์ (auto-save) → คงอยู่หน้าเดิมพร้อม toast/สถานะบันทึก
- ย้อนกลับ → CUS-NOTI-001 หรือ CUS-SET-001

## Components
- กลุ่มประเภทการแจ้งเตือน: เตือนการจอง, โปรโมชัน, สมาชิก — แต่ละรายการมี toggle
- กลุ่มช่องทาง: Push Notification, LINE, Email — toggle ตามที่รองรับ
- คำอธิบายย่อใต้แต่ละ toggle
- สถานะ "บันทึกแล้ว" / spinner ระหว่างบันทึก

## Validation Rules
- การสลับ toggle บันทึกทันที (auto-save) ไม่ต้องกดปุ่มยืนยัน
- ปิดทุกช่องทางของประเภทหนึ่ง = ไม่รับการแจ้งเตือนประเภทนั้น (อนุญาต)
- ช่องทางที่สนามไม่รองรับ → disabled พร้อมหมายเหตุ
- ค่ากำหนดผูกกับลูกค้าที่ล็อกอิน (ตาม tenant)

## API Dependencies
- `GET /api/v1/customers/{id}` — โหลดค่ากำหนดการแจ้งเตือนปัจจุบัน
- `PUT /api/v1/customers/{id}` — บันทึกค่ากำหนดที่เปลี่ยน

## Edge Cases
- บันทึกล้มเหลว → ย้อน toggle กลับสถานะเดิม + toast error
- ช่องทาง Push ถูกปิดที่ระบบปฏิบัติการ → แจ้งให้เปิดสิทธิ์ใน Settings ของเครื่อง
- โหลดค่ากำหนดล้มเหลว → ใช้ค่า default + ปุ่ม "ลองใหม่"
- ออฟไลน์ → ปิดการสลับ + แจ้งสถานะเชื่อมต่อ
- สลับเร็วหลายครั้ง → debounce ส่งค่าล่าสุดเท่านั้น

## Success Criteria
- เปิด/ปิดการแจ้งเตือนแต่ละประเภทและช่องทางได้ และบันทึกถูกต้อง
- ค่ากำหนดสะท้อนผลกับการรับการแจ้งเตือนจริง
- ช่องทางที่ไม่รองรับถูก disable ชัดเจน
- กรณีบันทึกล้มเหลว toggle ย้อนกลับสถานะเดิม
