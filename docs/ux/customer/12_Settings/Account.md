# CUS-SET-003 · Account

## Objective
- จัดการบัญชีของลูกค้า: ข้อมูลบัญชี/ช่องทางล็อกอิน, ออกจากระบบ, ลบบัญชี
- รวมการดำเนินการที่กระทบบัญชีไว้ในที่เดียวอย่างปลอดภัย

## User Story
> As a **Customer**, I want **จัดการบัญชีของฉัน เช่น ออกจากระบบหรือลบบัญชี**, so that **ควบคุมข้อมูลและการเข้าถึงบัญชีของฉันได้**.

## Entry Point
- จาก CUS-SET-001 (Settings) เมนู "บัญชี"

## Exit Point
- "แก้ไขข้อมูลส่วนตัว" → CUS-PROFILE-002 (Edit Profile)
- "ออกจากระบบ" → CUS-AUTH (Login) หลังยืนยัน
- "ลบบัญชี" → ยืนยันแล้วลบ → CUS-AUTH (Login)
- ย้อนกลับ → CUS-SET-001

## Components
- ข้อมูลบัญชี: อีเมล/เบอร์ที่ผูก, ช่องทางล็อกอิน (LINE/Google/Apple/OTP)
- ปุ่ม "แก้ไขข้อมูลส่วนตัว" (ไป CUS-PROFILE-002)
- ปุ่ม "ออกจากระบบ"
- ปุ่ม "ลบบัญชี" (สีเตือน Danger #EF4444) + คำอธิบายผลกระทบ
- Confirm dialog สำหรับออกจากระบบและลบบัญชี

## Validation Rules
- ออกจากระบบและลบบัญชีต้องมี confirm dialog ก่อนทำจริง
- ลบบัญชี: ต้องยืนยันซ้ำ (เช่น พิมพ์ยืนยัน/ติ๊กรับทราบ) เพราะกู้คืนไม่ได้
- ช่องทางล็อกอินหลักแสดงเป็น read-only
- การลบบัญชีต้องตรวจภาระผูกพันค้าง (ยอด Wallet/แพ็กเกจ/การจองที่ยังไม่จบ) ก่อนอนุญาต

## API Dependencies
- `GET /api/v1/customers/{id}` — ข้อมูลบัญชีและช่องทางล็อกอิน
- `PUT /api/v1/customers/{id}` — อัปเดต/ทำเครื่องหมายสถานะบัญชี (เช่น ขอลบ)

## Edge Cases
- มียอด Wallet/แพ็กเกจ/การจองค้าง → บล็อกการลบ + แจ้งให้จัดการก่อน
- ลบบัญชีล้มเหลว (5xx) → คงบัญชีเดิม + toast error
- ออกจากระบบขณะออฟไลน์ → เคลียร์ session local + sync เมื่อออนไลน์
- กดลบซ้ำระหว่างประมวลผล → ระบบรับครั้งเดียว
- token หมดอายุ → เด้งกลับ Login

## Success Criteria
- แสดงข้อมูลบัญชีและช่องทางล็อกอินถูกต้อง
- ออกจากระบบมี confirm และเคลียร์ session ครบ
- ลบบัญชีมีขั้นยืนยันซ้ำ และบล็อกเมื่อมีภาระค้าง
- กรณีล้มเหลวบัญชีไม่ถูกเปลี่ยนสถานะ
