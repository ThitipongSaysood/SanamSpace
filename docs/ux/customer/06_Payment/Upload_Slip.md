# CUS-PAY-003 · Upload Slip

## Objective
- ให้ลูกค้าอัปโหลดรูปสลิปการโอนเป็นหลักฐานการชำระเงิน
- ส่งสลิปเข้าระบบเพื่อทำ OCR Verification และตรวจสลิปซ้ำ (Duplicate Detection)
- เปลี่ยนสถานะการชำระเป็น "รอตรวจสอบ" เพื่อรอเจ้าหน้าที่อนุมัติ

## User Story
> As a **ลูกค้า (Customer)**, I want **อัปโหลดรูปสลิปการโอนเงิน**, so that **ระบบ/เจ้าหน้าที่ตรวจสอบและยืนยันการจองของฉันได้**.
>
> หมายเหตุ: การ Verify/Approve สลิปทำโดย Staff/Cashier ใน Owner portal — จอนี้เป็นฝั่งลูกค้าสำหรับอัปโหลดและติดตามสถานะเท่านั้น

## Entry Point
- มาจากจอโอนเงิน (CUS-PAY-002) เมื่อกด "อัปโหลดสลิป"

## Exit Point
- อัปโหลดสำเร็จ → ไปจอสถานะการชำระเงิน (CUS-PAY-004) สถานะ "รอตรวจสอบ"
- กดย้อนกลับ → กลับจอโอนเงิน (CUS-PAY-002)

## Components
- ปุ่มเลือกรูปจากแกลเลอรี / ถ่ายรูปสลิป
- พื้นที่พรีวิวรูปสลิปที่เลือก + ปุ่มลบ/เปลี่ยนรูป
- สรุปยอดที่ต้องชำระเทียบกับการจอง
- ตัวบ่งชี้สถานะกำลังอัปโหลด / กำลังตรวจ OCR (loading)
- ปุ่มหลัก "ยืนยันส่งสลิป" และปุ่มย้อนกลับ

## Validation Rules
- ต้องแนบรูปสลิป 1 ไฟล์ก่อนกดยืนยัน
- ชนิดไฟล์รองรับเฉพาะ JPG / PNG เท่านั้น
- ขนาดไฟล์ไม่เกิน 5 MB
- ยอดในสลิป (จาก OCR) ต้องตรงกับยอดการจอง (amount match)
- สลิปต้องไม่ซ้ำกับสลิปที่เคยใช้แล้ว (duplicate slip)

## API Dependencies
- `POST /api/v1/payments/{id}/upload-slip` — อัปโหลดรูปสลิปและเริ่ม OCR/ตรวจซ้ำ
- `GET /api/v1/payments` — ดึงสถานะ payment หลังอัปโหลด

## Edge Cases
- OCR อ่านสลิปไม่สำเร็จ → ยังส่งเข้าคิวตรวจด้วยเจ้าหน้าที่ พร้อมแจ้งผู้ใช้
- ตรวจพบสลิปซ้ำ (duplicate slip detected) → ปฏิเสธและขอสลิปใบจริง
- ยอดในสลิปไม่ตรง (wrong amount) → แจ้งเตือนและให้แนบสลิปใหม่
- ไฟล์ผิดชนิด/เกินขนาด → แสดง error ก่อนอัปโหลด
- การชำระหมดอายุก่อนส่งสลิป → บล็อกการส่งและแจ้งการจองหมดอายุ
- อัปโหลดล้มเหลว/เน็ตหลุด → ให้ลองใหม่โดยไม่ส่งซ้ำซ้อน

## Success Criteria
- อัปโหลดสลิปที่ถูกชนิด/ขนาด สำเร็จและ payment เปลี่ยนเป็น "รอตรวจสอบ"
- ระบบตรวจ OCR และ duplicate ทำงาน และบล็อกสลิปซ้ำ/ยอดไม่ตรง
- ผู้ใช้ถูกนำไปจอสถานะ (CUS-PAY-004) ทันทีหลังส่งสำเร็จ
