# CUS-PAY-004 · Payment Status

## Objective
- แสดงสถานะการชำระเงินของการจองแบบเรียลไทม์ (รอตรวจสอบ / สำเร็จ / ถูกปฏิเสธ / หมดอายุ)
- แจ้งผลการตรวจสลิปโดยเจ้าหน้าที่ และนำทางขั้นตอนถัดไป
- เป็นจุดติดตามผลหลังอัปโหลดสลิปหรือชำระด้วยช่องทางอื่น

## User Story
> As a **ลูกค้า (Customer)**, I want **เห็นสถานะการชำระเงินและผลการตรวจสลิป**, so that **รู้ว่าการจองได้รับการยืนยันแล้วหรือต้องดำเนินการอะไรต่อ**.

## Entry Point
- มาจากจออัปโหลดสลิป (CUS-PAY-003) หลังส่งสลิปสำเร็จ
- มาจากการชำระด้วย Wallet/Card (CUS-PAY-001) หรือลิงก์แจ้งเตือน/ประวัติการจอง

## Exit Point
- สถานะ "สำเร็จ" → ไปจอยืนยันการจอง (CUS-BOOK-002)
- สถานะ "ถูกปฏิเสธ" → กลับไปอัปโหลดสลิปใหม่ (CUS-PAY-003)
- สถานะ "หมดอายุ" → กลับไปจองใหม่ (CUS-BOOK-001)

## Components
- ป้ายสถานะหลัก (สี/ไอคอน): รอตรวจสอบ, สำเร็จ, ถูกปฏิเสธ, หมดอายุ
- การ์ดสรุปการจอง (สนาม/คอร์ต/วันเวลา) + ยอดที่ชำระ
- พรีวิวสลิปที่ส่งและเวลาที่ส่ง
- เหตุผลการปฏิเสธ (เมื่อ Staff/Cashier ปฏิเสธ)
- ปุ่มตามสถานะ: "ดูการจอง", "อัปโหลดสลิปใหม่", "จองใหม่"

## Validation Rules
- ต้องมีรายการ payment ผูกกับการจองจึงแสดงจอนี้ได้
- แสดงปุ่มดำเนินต่อเฉพาะที่ตรงกับสถานะปัจจุบันเท่านั้น
- สถานะอ่านจากระบบอย่างเดียว ลูกค้าแก้ไขสถานะเองไม่ได้

## API Dependencies
- `GET /api/v1/payments` — ดึงสถานะการชำระเงินล่าสุด (poll/refresh)
- `GET /api/v1/bookings/{id}` — ดึงสถานะการจองหลังชำระสำเร็จ

## Edge Cases
- OCR fail แต่ยังรอเจ้าหน้าที่ → คงสถานะ "รอตรวจสอบ" พร้อมข้อความอธิบาย
- ถูกปฏิเสธโดยเจ้าหน้าที่ (rejected by staff) → แสดงเหตุผลและปุ่มอัปโหลดใหม่
- ตรวจพบสลิปซ้ำ/ยอดไม่ตรง → สถานะปฏิเสธพร้อมระบุสาเหตุ
- การชำระหมดอายุ (payment expired) → แสดงสถานะหมดอายุและปุ่มจองใหม่
- โหลดสถานะล้มเหลว → แสดง error พร้อมปุ่มรีเฟรช

## Success Criteria
- สถานะที่แสดงตรงกับข้อมูลจริงและอัปเดตหลังเจ้าหน้าที่ตรวจสลิป
- แต่ละสถานะแสดงปุ่ม/เส้นทางถัดไปถูกต้อง (ยืนยัน/อัปโหลดใหม่/จองใหม่)
- กรณีปฏิเสธ ผู้ใช้เห็นเหตุผลและสามารถแก้ไขได้ทันที
