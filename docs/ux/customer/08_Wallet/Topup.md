# CUS-WALLET-002 · Topup

## Objective
- ให้ลูกค้าเลือกจำนวนเงินเติม Wallet (preset หรือกรอกเอง) แล้วยืนยันไปชำระเงิน
- เพิ่มยอดคงเหลือใน Wallet หลังชำระสำเร็จ และบันทึกเป็นธุรกรรมเติมเงิน

## User Story
> As a **Customer**, I want **เติมเงินเข้า Wallet ของฉัน**, so that **มียอดคงเหลือไว้ใช้จ่ายค่าจองสนามได้รวดเร็ว**.

## Entry Point
- จาก CUS-WALLET-001 (Wallet Overview) ปุ่ม "เติมเงิน"

## Exit Point
- ยืนยันจำนวน → CUS-PAY-001 (Payment / เลือกช่องทาง PromptPay/Card/Bank)
- ชำระสำเร็จ → กลับ CUS-WALLET-001 พร้อมยอดอัปเดต + toast สำเร็จ
- ยกเลิก → ย้อนกลับ CUS-WALLET-001 โดยไม่เติม

## Components
- จำนวนเงิน preset: ปุ่ม ฿100 / ฿300 / ฿500 / ฿1,000 (single-select)
- ช่องกรอกจำนวนเอง (custom amount) พร้อมหน่วย THB
- สรุปยอดที่จะเติม + คะแนนที่จะได้ (อัตรา 100 THB = 1 Point ถ้ามี)
- เลือกช่องทางชำระ (link ไป Payment)
- ปุ่มหลัก "ยืนยันเติมเงิน" / ปุ่มรอง "ยกเลิก"

## Validation Rules
- จำนวนเติมขั้นต่ำ/สูงสุดตามนโยบายสนาม (เช่น ขั้นต่ำ ฿50)
- จำนวนต้องเป็นตัวเลขบวก เป็นจำนวนเต็มบาท (หรือทศนิยม 2 ตามนโยบาย)
- ต้องเลือก preset หรือกรอก custom อย่างใดอย่างหนึ่งก่อนยืนยัน
- กันกดยืนยันซ้ำระหว่างสร้างรายการ (idempotent)

## API Dependencies
- `GET /api/v1/wallets` — อ้างอิง wallet id และยอดปัจจุบัน
- `POST /api/v1/wallets/{id}/adjust` — เพิ่มยอดเข้าสู่ Wallet หลังชำระสำเร็จ
- `GET /api/v1/wallets/{id}/transactions` — รีเฟรชธุรกรรมหลังเติม

## Edge Cases
- กรอกจำนวนต่ำกว่าขั้นต่ำ/เกินสูงสุด → แสดง inline error + disable ยืนยัน
- ชำระเงินไม่สำเร็จ/ยกเลิก → ไม่เพิ่มยอด ไม่บันทึกธุรกรรม
- ชำระสำเร็จแต่ adjust ล้มเหลว → reconcile ฝั่ง backend, แสดง "กำลังดำเนินการ" และ retry
- กดยืนยันซ้ำ → ระบบรับครั้งเดียว ป้องกันเติมซ้ำ
- ออฟไลน์ระหว่างยืนยัน → คงจำนวนที่เลือก แจ้งให้ลองใหม่

## Success Criteria
- เลือก/กรอกจำนวนถูกต้องและนำเข้าสู่ CUS-PAY-001
- ชำระสำเร็จ ยอด Wallet เพิ่มตรงตามจำนวนเติม
- ธุรกรรมเติมเงินบันทึกและแสดงใน Transactions
- กรณีล้มเหลว ไม่มีการเปลี่ยนยอดคงเหลือ
