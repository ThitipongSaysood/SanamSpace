# CUS-BOOK-004 · Booking Cancel

## Objective
- ให้ลูกค้ายกเลิกการจองที่ยังไม่ถึงเวลา และเข้าใจเงื่อนไขการคืนเงิน (refund policy) ก่อนยืนยัน
- คืน slot ที่ถูกล็อกกลับสู่ระบบให้ลูกค้ารายอื่นจองได้

## User Story
> As a **Customer**, I want **ยกเลิกการจองที่ทำไว้และเห็นว่าจะได้คืนเงินเท่าไร**, so that **ไม่เสียค่าใช้จ่ายเกินจำเป็นเมื่อไปไม่ได้ และปล่อยคอร์ทให้คนอื่น**.

## Entry Point
- จาก CUS-BOOK-003 (Booking History) การ์ด Upcoming → ปุ่ม "ยกเลิกการจอง"
- จากหน้ารายละเอียดการจอง (booking detail)

## Exit Point
- ยืนยันยกเลิกสำเร็จ → กลับ CUS-BOOK-003 (booking ย้ายไปแท็บ Cancelled) พร้อม toast ผลคืนเงิน
- ปิด/ไม่ยกเลิก → กลับจอเดิม โดยสถานะ booking ไม่เปลี่ยน

## Components
- Confirmation sheet/dialog "ยืนยันการยกเลิก?"
- สรุป booking ที่จะยกเลิก: คอร์ท, วันที่, ช่วงเวลา, ยอดที่ชำระ
- กล่องแสดงนโยบายคืนเงิน: ยอดคืนที่คำนวณได้ + ช่องทางคืน (Wallet/โอนคืน)
- (ทางเลือก) Dropdown "เหตุผลการยกเลิก"
- ปุ่มหลัก "ยืนยันยกเลิก" (สีเตือน/แดง) / ปุ่มรอง "ไม่ยกเลิก"

## Validation Rules
- ยกเลิกได้เฉพาะ booking สถานะ confirmed/pending_payment ที่ยังไม่ถึงเวลาเริ่ม
- ต้องอยู่ในหน้าต่างยกเลิกตามนโยบายสนาม (เช่น ก่อนเวลาเริ่ม ≥ X ชม.) มิฉะนั้น disable ปุ่มยืนยัน
- คำนวณยอดคืนตามนโยบาย: ยกเลิกล่วงหน้า = คืนเต็ม, ใกล้เวลา = คืนบางส่วน/ไม่คืน
- ยกเลิกแล้ว slot ต้องถูกปล่อยคืน schedule ทันที

## API Dependencies
- `POST /api/v1/bookings/{id}/cancel` — ยกเลิกการจองและทริกเกอร์การคืน slot
- `GET /api/v1/bookings/{id}` — ดึงรายละเอียด/หน้าต่างยกเลิกก่อนแสดง dialog
- `POST /api/v1/refunds` — สร้างคำขอคืนเงิน (เฉพาะแพ็กเกจ Business+ ที่มี Refund Management)

## Edge Cases
- เลยหน้าต่างยกเลิก → disable ปุ่มและแสดงเหตุผล "เลยกำหนดยกเลิก"
- กดยกเลิกพร้อมกันหลายครั้ง/ซ้ำ → idempotent, ครั้งถัดไปคืน 409/แจ้ง "ยกเลิกไปแล้ว"
- booking ถูก check-in ไปแล้ว → ยกเลิกไม่ได้, ซ่อน/disable ปุ่ม
- แพ็กเกจสนามเป็น Starter (ไม่มี Refund Management) → ยกเลิกได้แต่ไม่สร้าง refund อัตโนมัติ, แจ้งให้ติดต่อสนาม
- network error ระหว่างยืนยัน → ไม่เปลี่ยนสถานะ, ให้ลองใหม่

## Success Criteria
- ยืนยันยกเลิกแล้ว booking เปลี่ยนเป็น cancelled และ slot ถูกปล่อยคืนทันที
- ยอดคืนเงินที่แสดงตรงกับนโยบายและผลที่เกิดจริง
- ปุ่มยืนยันถูก disable เมื่อเลยหน้าต่างยกเลิกหรือ booking เช็คอินแล้ว
- การกดยกเลิกซ้ำไม่ทำให้เกิดผลซ้ำซ้อน (idempotent)
