# CUS-BOOK-005 · Check In

## Objective
- แสดง QR Code ของการจอง (Booking Flow ขั้น 9) ให้พนักงานสแกนเมื่อลูกค้าถึงสนาม เพื่อยืนยันการเข้าใช้
- แสดง countdown "เข้าใช้ได้ภายใน" ให้ลูกค้ารู้กรอบเวลาเช็คอิน

## User Story
> As a **Customer**, I want **เปิด QR ของการจองให้พนักงานสแกนตอนถึงสนาม**, so that **เข้าใช้คอร์ทได้รวดเร็วโดยไม่ต้องแจ้งรายละเอียดด้วยปากเปล่า**.

## Entry Point
- จาก CUS-BOOK-003 (Booking History) การ์ด Upcoming → ปุ่ม "QR Check-in"
- จาก CUS-BOOK-002 (Confirmation) → "ดูรายละเอียดการจอง"
- จาก LINE reminder ก่อนถึงเวลาจอง

## Exit Point
- พนักงานสแกนสำเร็จ → สถานะ booking = checked_in, แสดงผล "เช็คอินสำเร็จ" (ต่อด้วย CUS-BOOK-006 เมื่อจบการใช้งาน)
- ปิด/ย้อนกลับ → CUS-BOOK-003

## Components
- หัวข้อ "แสดง QR ให้พนักงานสแกน เมื่อถึงสนาม"
- QR Code ขนาดใหญ่กลางจอ
- Booking Code ใต้ QR (เช่น BK240S250012)
- สรุป: ชื่อคอร์ท (Court 1), วันที่ (เช่น เสาร์ 25 พ.ค. 2567), ช่วงเวลา (18:00–19:00)
- Countdown timer "เข้าใช้ได้ภายใน" รูปแบบ ชม.:นาที:วินาที (เช่น 00:15:32)
- (สถานะ) แบดจ์ "เช็คอินแล้ว" เมื่อสแกนสำเร็จ

## Validation Rules
- แสดง QR ได้เฉพาะ booking สถานะ confirmed และอยู่ในหน้าต่างเช็คอิน (เช่น ก่อนเวลาเริ่ม X นาที จนถึงสิ้นสุด grace period)
- QR ต้องผูกกับ booking_id + token หมดอายุ (rotate/expire ตามเวลา) เพื่อกันการแชร์/นำกลับมาใช้ซ้ำ
- เช็คอินได้ครั้งเดียวต่อ booking (ไม่ซ้ำ)
- countdown สิ้นสุด = QR หมดอายุ และต้องปิดการเช็คอินตามนโยบาย no-show

## API Dependencies
- `GET /api/v1/bookings/{id}` — ดึงข้อมูล booking + token/payload สำหรับสร้าง QR + เวลา
- `POST /api/v1/bookings/{id}/checkin` — บันทึกการเช็คอินเมื่อพนักงานสแกน (ฝั่ง staff เรียก)

## Edge Cases
- QR หมดอายุ/เลยหน้าต่างเช็คอิน → แสดง "QR หมดอายุ" + แนะนำติดต่อพนักงาน
- QR ไม่ถูกต้อง/booking ถูกยกเลิก → สแกนแล้วปฏิเสธ พร้อมข้อความเหตุผล
- มาก่อนเวลาเช็คอิน → แสดง countdown "ยังไม่ถึงเวลาเข้าใช้" และยังไม่เปิดให้สแกน
- เช็คอินซ้ำ → คืน 409/แจ้ง "เช็คอินไปแล้ว"
- ออฟไลน์ฝั่งลูกค้า → ยังแสดง QR ที่แคชไว้ได้ แต่ countdown/สถานะอาจไม่อัปเดต
- no-show (ไม่เช็คอินจนหมดเวลา) → booking ถูกทำเครื่องหมาย no-show ตามนโยบายสนาม

## Success Criteria
- QR แสดงถูกต้อง ผูกกับ booking ที่ถูกต้อง และพนักงานสแกนแล้วเปลี่ยนสถานะเป็น checked_in
- QR ที่หมดอายุ/ของ booking ที่ยกเลิก สแกนไม่ผ่าน
- เช็คอินซ้ำไม่เกิดผลซ้ำซ้อน (idempotent)
- countdown แสดงเวลาคงเหลือถูกต้องและสอดคล้องกับหน้าต่างเช็คอิน
