# CUS-PKG-002 · Package Detail

## Objective
- แสดงรายละเอียดแพ็กเกจที่เลือก: จำนวนชั่วโมง/สิทธิ, ราคา, ระยะเวลาใช้สิทธิ (อายุแพ็กเกจ), เงื่อนไข
- ให้ลูกค้ายืนยันซื้อและนำไปชำระเงิน

## User Story
> As a **Customer**, I want **ดูรายละเอียดและเงื่อนไขของแพ็กเกจก่อนซื้อ**, so that **มั่นใจในสิทธิและระยะเวลาใช้งานก่อนชำระเงิน**.

## Entry Point
- จาก CUS-PKG-001 (Package List) กดการ์ดแพ็กเกจ

## Exit Point
- กด "ซื้อแพ็กเกจ" → CUS-PAY-001 (Payment) หรือชำระด้วย Wallet
- ชำระสำเร็จ → CUS-PKG-003 (My Packages) พร้อม toast สำเร็จ
- ย้อนกลับ → CUS-PKG-001 โดยไม่ซื้อ

## Components
- หัวข้อแพ็กเกจ + ราคา + ราคาต่อชั่วโมง
- รายละเอียดสิทธิ: จำนวนชั่วโมง/รอบเดือน, กีฬา/คอร์ทที่ใช้ได้, ช่วงเวลาที่ใช้ได้ (เช่น Off-Peak)
- อายุการใช้สิทธิ (วันหมดอายุนับจากวันซื้อ)
- เงื่อนไขและข้อกำหนด (terms) แบบ bullet
- เลือกช่องทางชำระ (Wallet / อื่นๆ)
- ปุ่มหลัก "ซื้อแพ็กเกจ" / ปุ่มรอง "ย้อนกลับ"

## Validation Rules
- ราคา/สิทธิ/อายุดึงจาก config สนามล่าสุด (รีเฟรชก่อนซื้อ)
- ถ้าชำระด้วย Wallet → ยอดคงเหลือต้องเพียงพอ มิฉะนั้นเสนอเติมเงิน
- ต้องยอมรับเงื่อนไข (ถ้ากำหนด) ก่อนยืนยัน
- กันกดซื้อซ้ำระหว่างประมวลผล (idempotent)

## API Dependencies
- `GET /api/v1/wallets` — ตรวจยอดคงเหลือกรณีชำระด้วย Wallet
- `POST /api/v1/wallets/{id}/adjust` — หักยอดเมื่อชำระด้วย Wallet
- — (สร้างรายการซื้อแพ็กเกจผ่าน catalog/booking ของ tenant)

## Edge Cases
- ยอด Wallet ไม่พอ → ปุ่ม "เติมเงิน" ไป CUS-WALLET-002
- แพ็กเกจหมดช่วงขาย/ถูกปิดระหว่างดู → บล็อกการซื้อ + แจ้งเตือน
- ชำระล้มเหลว → ไม่สร้างสิทธิแพ็กเกจ ไม่หักยอด
- กดซื้อซ้ำ → ระบบรับครั้งเดียว
- ออฟไลน์ → ปิดปุ่มซื้อ + แจ้งสถานะเชื่อมต่อ

## Success Criteria
- แสดงรายละเอียด สิทธิ อายุ และเงื่อนไขครบถ้วน
- ซื้อสำเร็จและแพ็กเกจปรากฏใน CUS-PKG-003 (My Packages)
- ชำระด้วย Wallet หักยอดถูกต้อง ; ยอดไม่พอเสนอเติมเงิน
- กรณีล้มเหลวไม่มีการหักยอด/สร้างสิทธิ
