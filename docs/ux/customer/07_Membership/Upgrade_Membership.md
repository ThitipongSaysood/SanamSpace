# CUS-MEMBER-003 · Upgrade Membership

## Objective
- ให้ลูกค้าเลือกอัปเกรดระดับสมาชิก (เช่น Silver → Gold → Platinum) และยืนยัน
- แสดงสรุปสิทธิที่จะได้รับเพิ่ม + ค่าใช้จ่าย/เงื่อนไข (คะแนน/ค่าธรรมเนียม) ก่อนยืนยัน
- สร้างรายการอัปเกรดและนำไปชำระเงิน (ถ้ามีค่าใช้จ่าย)

## User Story
> As a **Customer**, I want **อัปเกรดระดับสมาชิกเป็นระดับที่สูงขึ้น**, so that **ได้รับสิทธิประโยชน์เพิ่ม เช่น ส่วนลดและคะแนนพิเศษ**.

## Entry Point
- จาก CUS-MEMBER-001 (Overview) ปุ่ม "อัปเกรด"
- จาก CUS-MEMBER-002 (Tiers) ปุ่ม "อัปเกรดเป็น Gold/Platinum"

## Exit Point
- ยืนยันและมีค่าใช้จ่าย → CUS-PAY-001 (Payment)
- ยืนยันแบบใช้คะแนน/ฟรี และสำเร็จ → กลับ CUS-MEMBER-001 พร้อม toast สำเร็จ
- ยกเลิก → ย้อนกลับจอต้นทาง โดยไม่เปลี่ยนระดับ

## Components
- ระดับเป้าหมายที่เลือก พร้อมสีและสิทธิที่จะได้รับเพิ่ม (delta จากระดับปัจจุบัน)
- สรุปเงื่อนไข: คะแนนที่ต้องใช้ / ค่าธรรมเนียม / ระยะเวลามีผล
- Checkbox ยอมรับเงื่อนไขสมาชิก
- ปุ่มหลัก "ยืนยันอัปเกรด" / ปุ่มรอง "ยกเลิก"

## Validation Rules
- เลือกได้เฉพาะระดับที่สูงกว่าระดับปัจจุบัน (ไม่อนุญาต downgrade/same level)
- ต้องติ๊กยอมรับเงื่อนไขก่อนกดยืนยัน
- ถ้าใช้คะแนนแลก → คะแนนคงเหลือต้องเพียงพอ มิฉะนั้น disable ปุ่มยืนยัน
- กันการกดซ้ำ (idempotent) ระหว่างรอผลอัปเกรด

## API Dependencies
- `GET /api/v1/memberships` — ตรวจระดับปัจจุบันและเงื่อนไขอัปเกรด
- `POST /api/v1/memberships` — สร้าง/ยืนยันการอัปเกรดระดับสมาชิก
- `GET /api/v1/customers/{id}` — ตรวจคะแนนคงเหลือสำหรับแลกอัปเกรด

## Edge Cases
- คะแนนไม่พอ → แสดงข้อความและปุ่ม "สะสมเพิ่ม" / ปิดปุ่มยืนยัน
- อัปเกรดล้มเหลว (4xx/5xx) → toast error + ไม่หักคะแนน/ไม่เปลี่ยนระดับ
- ชำระเงินไม่สำเร็จ → ระดับยังคงเดิม ยกเลิกรายการอัปเกรด
- กดยืนยันซ้ำระหว่างประมวลผล → ระบบรับเพียงครั้งเดียว
- ระดับปัจจุบันเป็น Platinum → บล็อกการเข้าหน้านี้พร้อมแจ้ง "ระดับสูงสุดแล้ว"

## Success Criteria
- ยืนยันอัปเกรดสำเร็จและระดับสมาชิกเปลี่ยนเป็นระดับเป้าหมาย
- กรณีมีค่าใช้จ่ายนำเข้าสู่ CUS-PAY-001 ถูกต้อง
- คะแนน/ค่าธรรมเนียมถูกหักตรงตามเงื่อนไขที่แสดง
- กรณีล้มเหลว ไม่มีผลข้างเคียงต่อระดับ/คะแนน
