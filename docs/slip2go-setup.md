# วิธีตั้งค่า Slip2Go (ตรวจสลิปอัตโนมัติ)

คู่มือทีละขั้น — เอาค่าจากที่ไหน ใส่ตรงไหน และทดสอบยังไง

> อัปเดต: 2026-08-11 · ผู้ทำ: **แอดมินแพลตฟอร์ม** (ไม่ใช่เจ้าของสนาม) เพราะเป็น
> บัญชี Slip2Go เดียวที่ทุกสนามใช้ร่วมกัน · โครงเบื้องหลัง: [slip-verification-flow.md](slip-verification-flow.md)

---

## ภาพรวม 3 ขั้น

1. **ที่ Slip2Go** — เอา API Secret + ยืนยัน endpoint
2. **ที่หน้าแอดมินเรา** — ใส่ค่า + เปิดสวิตช์รวม
3. **ที่สนาม (owner)** — เปิดสวิตช์ของสนาม + ตั้งเลขบัญชี แล้วทดสอบ

---

## ขั้นที่ 1 — เอาค่าจาก Slip2Go

### 1.1 สมัคร + เติมโทเคน

- สมัครที่ [slip2go.com](https://slip2go.com) แล้วเติมโทเคน (API คิด ~0.5 โทเคน/สลิป)
- โทเคนต้องมีพอ ไม่งั้น provider จะตอบไม่สำเร็จ → ระบบตกไปตรวจเอง

### 1.2 คัดลอก API Secret

เมนู **API Connect → Authentication**

- คัดลอกค่า **API Secret** (บางที่เรียก Secret Key) เก็บไว้
- ดูด้วยว่า header ที่เขาให้ใช้เป็นแบบ `Authorization: Bearer <secret>` หรือไม่
  (ระบบเราส่งแบบนี้ ถ้าเขาใช้ชื่อ header อื่นต้องแจ้งให้แก้ driver)

### 1.3 ยืนยัน endpoint (REST API — สำคัญ)

เมนู **API Connect → REST API** → ใช้ตัว **QR Code** (`verify-slip/qr-code/info`)

- ✅ ใช้ **REST API** (แบบ sync — ยิงแล้วรอผลทันที)
- ❌ **อย่าใช้ Queue API** (แบบ async ต้องรอ webhook — ระบบเราไม่รองรับเส้นทางนี้)
- URL ที่ระบบใช้เป็น default อยู่แล้วคือ
  `https://connect.slip2go.com/api/verify-slip/qr-code/info`
  ถ้าหน้า REST API โชว์ URL เดียวกัน → ช่อง Endpoint **เว้นว่างได้**
  ถ้าโชว์ URL อื่น (host/branch ต่าง) → คัดลอกมาใช้ในขั้นที่ 2

> เมนูที่ **ไม่ต้องยุ่ง**: "ตรวจสลิป" (จัดการสลิป/ตรวจผ่าน LINE/Facebook/ตั้งค่าการ
> ตรวจสลิป) คือระบบตรวจในตัวของ Slip2Go เอง · "สร้าง QR Code" ก็ไม่ต้องใช้ (สนามมี
> PromptPay ของตัวเอง)

## ขั้นที่ 2 — ใส่ค่าที่หน้าแอดมินเรา

ไปที่ **แอดมิน → ตั้งค่า (Settings) → แท็บ "การชำระเงิน" → การ์ด "ตรวจสลิปอัตโนมัติ (Slip2Go)"**

| ช่องในระบบ | ใส่อะไร |
|---|---|
| **เปิดใช้งานทั้งระบบ (สวิตช์รวม)** | เปิด ✅ |
| **ผู้ให้บริการ** | เลือก **Slip2Go** |
| **API Secret** | วางค่าจากขั้น 1.2 *(เป็น write-only — เซฟแล้วจะไม่แสดงกลับ ขึ้นแค่ "ตั้งค่าแล้ว")* |
| **Endpoint** | เว้นว่างถ้าใช้ค่าเริ่มต้น · หรือวาง URL จากขั้น 1.3 |

กด **บันทึกการเปลี่ยนแปลง**

> ค่าเหล่านี้เก็บใน `platform_settings` (key เข้ารหัสที่ระดับฐานข้อมูล) — ไม่ต้อง
> แตะ `.env` บนเซิร์ฟเวอร์

**ความหมายของสวิตช์รวม:** ปิดที่นี่ = ทุกสนามหยุดตรวจอัตโนมัติทันที ไม่ว่าแพ็กเกจหรือ
สวิตช์ของสนามจะเปิดอยู่ (ปุ่มฉุกเฉินตอน provider มีปัญหา/คุมค่าใช้จ่าย)

---

## ขั้นที่ 3 — เปิดใช้ที่สนาม (owner) + ทดสอบ

### 3.1 ให้สิทธิ์แพ็กเกจ

ตรวจสลิปอัตโนมัติเป็นฟีเจอร์ของ **Business / Pro** (มีอยู่แล้วผ่านฟีเจอร์
`slip_auto_verify`) — สนามที่จะใช้ต้องอยู่แพ็กเกจนี้

### 3.2 ฝั่งสนาม

**สนาม → ตั้งค่า → หน้าจ่ายเงิน:**

1. ตั้ง **PromptPay / เลขบัญชีธนาคาร** ของสนามให้ถูกต้อง
   (ระบบเทียบเลข 4 ตัวท้ายของผู้รับในสลิป กับเลขนี้ — ผิด = ตกไปตรวจเอง)
2. เปิดสวิตช์ **"ตรวจสลิปอัตโนมัติ"**

### 3.3 ทดสอบจริง 1 ใบ

1. ให้ลูกค้า (หรือทดสอบเอง) จอง + โอน + แนบสลิปจริง
2. ดูผล:
   - โอนถูกบัญชี ยอดพอ สลิปจริง → payment ควรขึ้น **approved** เอง
   - หน้า **owner/payments** จะโชว์ "🔎 อ่านจากสลิป ฿… · จาก …"
3. ถ้าไม่ auto-approve → เปิดดู `payment_slips.verify_payload` (response ดิบจาก
   Slip2Go) เทียบว่าฟิลด์ตรงกับที่ระบบ map ไหม — ถ้าคีย์ต่าง แก้ path ที่
   `backend/app/Services/Slip/Slip2GoVerifier.php` (จุดเดียว)

## เกณฑ์ที่ต้องผ่านครบ ระบบจึงอนุมัติเอง

| # | เงื่อนไข | ไม่ผ่านแล้วเกิดอะไร |
|---|---|---|
| 1 | สวิตช์รวมแพลตฟอร์มเปิด (แอดมิน) | ทุกสนามตรวจเอง |
| 2 | แพ็กเกจ Business/Pro | สนามนั้นตรวจเอง |
| 3 | สวิตช์สนามเปิด (owner) | สนามนั้นตรวจเอง |
| 4 | ยังไม่เกินเพดาน 1,000 ครั้ง/เดือน | ตรวจเองจนสิ้นเดือน |
| 5 | สลิปไม่ซ้ำ | ติดธง "เคยใช้แล้ว" |
| 6 | **สลิปจริง + ยอดถึง + เข้าบัญชีสนามเอง** | ตรวจเอง |

**ปรัชญา:** ไม่ชัวร์เมื่อไหร่ → เข้าคิวตรวจเองเสมอ ไม่มีอนุมัติผิดแบบเงียบๆ

## แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุ/วิธีแก้ |
|---|---|
| เปิดสวิตช์ที่สนามแล้วเด้ง 402 | สนามไม่ได้อยู่แพ็กเกจ Business/Pro |
| เปิดครบแต่ auto ไม่ทำงาน | สวิตช์รวม (แอดมิน) ปิดอยู่ · หรือ ผู้ให้บริการยังเป็น "ปิด/null" · หรือ Secret ผิด |
| อ่านยอด/ผู้รับผิด | เทียบ `verify_payload` แล้วปรับ mapping ใน `Slip2GoVerifier.php` |
| provider ตอบไม่สำเร็จตลอด | โทเคน Slip2Go หมด · Secret/endpoint ผิด · ใช้ Queue API แทน REST |
| ทุกสลิปตกไปตรวจเอง | เลขบัญชีสนามไม่ตรงกับผู้รับในสลิป (เช็คขั้น 3.2) |

## ทางเลือกสำหรับ dev / CI (ตั้งผ่าน .env แทน DB)

ถ้าเป็นเครื่องทดสอบและไม่อยากเข้าหน้าแอดมิน:

```env
SLIP_VERIFY_ENABLED=true
SLIP_VERIFY_DRIVER=slip2go
SLIP_VERIFY_KEY=<API Secret>
# SLIP_VERIFY_ENDPOINT=  # เว้นว่าง = ใช้ค่าเริ่มต้นของ driver
```

แล้ว `php artisan config:clear` — ค่าใน DB (ถ้ามี) จะชนะ env เสมอ; env เป็นแค่
fallback

## สรุปสั้น

1. Slip2Go → **API Connect → Authentication** เอา **API Secret**
2. แอดมิน → ตั้งค่า → การชำระเงิน → เปิดสวิตช์รวม · เลือก **Slip2Go** · วาง Secret · เว้น Endpoint
3. สนาม → ตั้งเลขบัญชีให้ตรง + เปิดสวิตช์ (ต้อง Business/Pro) → **ยิงทดสอบ 1 ใบ**
